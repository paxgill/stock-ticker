# PG Stock Analysis

A self-hosted stock **watchlist + rule-based signal terminal**. It runs on free
market data (yfinance), keeps every signal transparent and explainable (no ML, no
black boxes), and optionally layers in a Claude-powered intelligence layer when you
provide an API key.

> **Disclaimer:** All output is **algorithmic and is not financial advice**. Signals,
> backtests, and AI explanations are illustrative only. Do your own research before
> trading. Backtest results are hypothetical and not indicative of future returns.

---

## Features

**Watchlist & dashboard**
- Live quotes with cache + single-call batch fetch; stale-data banner on outages
- Tiered watchlist, free-form **tags** with a tag filter, per-ticker notes
- 14-day **earnings strip**, pre/after-hours prices, 52-week range
- Persistent **status rail**: market session + NY clock, indices, refresh age, active profile

**Signal engine (regime-aware, transparent)**
- Indicators: Wilder RSI, MACD, ADX/DI, ATR/ATR%, Bollinger %B, OBV slope, 12-1 momentum
- Four **market regimes** (trend strength × volatility) that reweight signal families
- Composite score across four families (trend / momentum / volume-flow / oscillator)
  with two confirmation rules, an ATR-based **suggested stop**, and a position-size hint
- Click any signal card for a **breakdown**: family contributions, regime inputs,
  confirmation outcomes, and the stop math
- Research-grounded **strategy presets** (momentum, mean-reversion, trend-following,
  quality+value, low-vol) and a custom profile editor

**Backtesting**
- Walk-forward **backtest tab**: replay the engine day-by-day, ATR stops, equity vs
  buy-and-hold, hit rate / profit factor / max drawdown / exposure (hypothetical banner)

**Portfolio & journal**
- Portfolio tracker with **FIFO realized P&L** auto-fill on sells and blended cost basis
- Trade journal with CSV export and a cumulative P&L chart

**Analytics**
- Sector heatmap, correlation matrix, **compare mode** (normalized %-change overlay),
  per-ticker news with sentiment (Finnhub)

**Alerts**
- Price alerts checked **server-side** by a background thread (works with no browser
  open), recorded as events, with an optional **webhook** (Slack/Discord/Zapier)

**Claude Fable 5 intelligence layer** (optional, key-gated)
- Morning briefing, signal explanations, journal review, natural-language watchlist
  search, and backtest postmortems — each cached, labeled "Generated by Claude", and
  ending with the disclaimer. Absent entirely when no key is set.

**Platform**
- Dual **light/dark themes** (charts included), inline SVG iconography, keyboard
  shortcuts, **PWA** shell (installable, offline last-known quotes), Electron desktop
  wrapper, and an iOS Scriptable widget generator.

## Quick start (local)

```bash
pip install -r requirements.txt
python app.py
# open http://localhost:5000
```

SQLite is used locally (data in `./data/terminal.db`). No keys required — the app
runs fully on its rule-based engine and free yfinance data.

## Deploy (Railway / Render)

Uses gunicorn via the `Procfile`:

```
web: gunicorn app:app --bind 0.0.0.0:$PORT --workers 2 --threads 4 --timeout 90
```

Set `DATABASE_URL` to a Postgres URL and the app switches from SQLite automatically
(`postgres://` is normalized to `postgresql://`). Schema changes are applied at
startup by an idempotent migration helper — no Alembic needed.

Health probe: `GET /api/health` → `{ok, db, yfinance_age_s, version}`.

## Environment variables

| Variable | Enables | Notes |
|---|---|---|
| `DATABASE_URL` | Postgres instead of SQLite | optional |
| `FMP_API_KEY` | Fundamentals (growth, FCF, short interest) | Financial Modeling Prep free tier |
| `FINNHUB_API_KEY` | News feed with sentiment | Finnhub free tier |
| `ANTHROPIC_API_KEY` | Claude Fable 5 layer | usage-based; responses are short + cached. See SETUP.md |
| `DISABLE_ALERT_ENGINE` | Turn off the background alert thread | set to any value |

All keys are optional; every key-gated feature degrades gracefully when unset.

## How the signal engine works

The engine is a transparent, rule-based composite — every number is reproducible and
comes with a plain-English reason.

1. **Indicators** (`indicators.py`): Wilder-smoothed RSI/ATR/ADX (matching charting
   platforms), MACD, Bollinger %B, OBV slope, and academic 12-1 momentum. Pure
   functions, pandas in / values out, unit-tested against fixtures.
2. **Regime detection** (`analysis.py::detect_regime`): ADX (trend strength) and ATR%
   vs its own 50-day median (volatility) classify each ticker into Trending/Ranging ×
   Calm/Volatile. Indicator reliability is regime-dependent, so each regime reweights
   the signal families (e.g. oscillators dominate in ranges; trend signals are muted).
3. **Composite scoring**: each signal contributes a score in `[-1, +1]` within one of
   four families — **trend, momentum, volume-flow, oscillator**. Confidence is a
   regime-adjusted weighted mean mapped to 0–100, then gated by two confirmation rules:
   a BUY/SELL needs **≥2 independent families agreeing**, and a signal **against the
   regime trend is capped to HOLD**.
4. **Actionable output** (illustrative, not advice): an ATR-based suggested stop
   (1.5× ATR, tightened to 1.2× in ranges, widened to 2× in volatile trends) and a
   risk-based position-size hint from the profile's risk tolerance.

The **backtester** (`backtest.py`) replays `analyze_ticker` on an expanding window with
next-open execution and the ATR stop, then reports equity vs buy-and-hold and the usual
stats. Results are hypothetical and never persisted or ranked.

## Signal Scoreboard & Time Machine

Two features that share **one point-in-time engine** (`analysis.replay_signals`) —
the same primitive the backtester uses — so a signal can only ever be computed
from bars dated on or before the day in question. A loud test proves a
reconstruction at date *t* is byte-identical whether or not future bars exist in
the input.

**Information Coefficient (IC)** is the headline metric: the rank correlation
between the engine's continuous signed score and the realized forward return.
Read it as: **> 0.05 = meaningful predictive power, ≈ 0 = noise, < −0.05 =
contrarian** (doing the opposite would have helped). The watchlist number is the
*cross-sectional* rank IC averaged over dates with ≥5 names; per-ticker it's the
time-series IC. Every metric shows its sample size `n`, and `n < 20` is flagged
"noisy" — never hidden.

**Backfill vs. live.** "Backfill" instantly replays the last N months of
point-in-time signals so the scoreboard is useful on day one; "live" snapshots
are written once per trading day after the close by the existing daemon thread
and carry zero hindsight risk (they're marked distinctly).

**Honesty caveats (shown in-app, repeated here):**
- *Lookahead:* signals are reconstructed strictly from prior bars; this is tested.
- *Survivorship:* your watchlist is names you chose and kept — a flattering sample.
- *Split-adjusted prices:* all math uses split/dividend-adjusted prices (so
  RSI/returns stay continuous). Displayed historical prices are labeled
  "split-adjusted," and when a corporate action sits between the shown date and
  today, the as-traded price and a note are surfaced so the number matches memory.
- *Execution lag:* next-open ("no") returns are shown beside close-to-close so you
  see how much "edge" is timing fantasy.
- *Anecdote vs. evidence:* the Time Machine shows one rewound date (a story) plus
  2–3 other dates; the IC across all dates is the evidence. The UI says so.
- **Nothing auto-tunes the engine.** The scoreboard reports; it never optimizes
  profile weights to past IC (that would be overfitting).

The **Time Machine** (rewind icon on any signal card, or the scoreboard drawer)
reconstructs the full signal panel as of any past date — visually identical to a
live card — and shows the realized outcome at 1/5/10/20 days and "to today" beside
it. Dates lacking enough history (e.g. MA200 needs 200 trading days) are disabled
or flagged, never fabricated.

## Tests

```bash
python tests/test_indicators.py   # indicator fixtures
python tests/test_engine.py       # regime gating + confirmation rules
python tests/test_backtest.py     # walk-forward correctness + perf budget
python tests/test_portfolio.py    # FIFO math + product endpoints
python tests/test_ai.py           # AI layer graceful degradation
python tests/test_routes.py       # API smoke tests
python tests/test_scoreboard.py   # lookahead guard, IC, forward returns, time-machine
```

Each script asserts its expectations and exits non-zero on failure, so they drop
straight into CI. `tests/conftest.py` also puts the repo root on the import path for
`pytest` collection.
